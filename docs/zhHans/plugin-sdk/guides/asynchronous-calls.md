# 异步调用、预算与不确定结果

一次调用可能直接返回值，也可能返回继续执行的任务句柄，还可能在外部副作用已经发生后失去结果。把这三种情况分开处理。

## 调用完成不等于任务完成

AbiReply 描述一次调用。返回 OperationRef 时，Success 只表示已接受工作，应继续读取或订阅任务。下载开始不等于文件校验成功，启动请求成功也不等于游戏进入主菜单。

C/Wasm 调用序列化 continuation 后让出执行，下次 resume 收到回复。先检查 `nx_reply_success`，再用对应 `_result` 解码。托管代码应 await 并保留结构化错误，不要返回默认值掩盖失败。

## 预算是剩余时间

宿主分配截止时间，调用者只能缩短它。阶段视图继承剩余预算和取消；重新创建包装器不会重置计时。Provider 排队也消耗相同预算。

取消请求终止工作，但不会撤销已完成的写文件、请求或进程启动。副作用可能已经发生时，应检查实际任务记录。

## 有依据地重试

一次新的预期副作用使用新的幂等键；解决同一次不确定调用时，保留原键和原输入。用旧键发送不同输入是冲突，用新键绕过可能重复执行。

OUTCOME_UNKNOWN 应保持为不确定状态。检查日志、任务或外部实际状态，不能把它展示为“失败，可以安全重试”。订阅、绑定和计划属于当前加载；结束后通过对应释放接口清理，不存在可假定的万能释放操作。
