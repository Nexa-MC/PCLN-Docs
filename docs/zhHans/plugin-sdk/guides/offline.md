# 让插件在离线时仍然有用

区分 SDK 构建依赖、Market 准入与功能自己的网络请求。缓存其中一项，并不自动满足另外两项。

## 离线构建

联网完成一次模板构建，保留编译器、已验证的 `.sdk` 缓存及源归档。之后可以校验缓存并离线编译。缓存缺失或损坏时需要重新获得锁定的发布包；不要悄悄改为下载 main 分支。

## 离线运行

宿主可以在其策略允许范围内保存已批准的加密包及验证材料。SDK 不颁发权益、不持有 Market 私钥，也不决定过期和撤销策略。记录的生产 Market 集成仍未完成，因此不能承诺尚未定义的统一离线授权期限。

把必要的 NXML 和静态资源放入包中，使用授权存储保存本地偏好。能降级的远程目录、账户刷新和在线服务应设计为可选。缓存结果应显示观察时间，不能冒充最新响应。

## 重新联网

区分待提交意图与已经提交的远程状态。恢复网络后先重新读取版本，再应用修改；发生冲突时合并或重新生成计划。不能因为网络恢复就自动重放不确定的写操作。

完成本地准入后断网重启，验证页面与本地数据，再逐项测试依赖远程服务的功能。恢复网络后检查读取恢复、写操作不重复，并确认离线模式不会绕过被拒绝的权限。
