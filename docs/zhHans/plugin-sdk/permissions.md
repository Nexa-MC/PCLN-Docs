# 权限、资源归属与用户确认

一次调用必须同时满足能力契约、权限、生命周期阶段和目标范围。通过其中一项检查，不代表通过其他检查。

## 为实际功能声明需求

清单请求权限，宿主决定授权。只有缺失后无法提供核心功能的能力才应声明为必需；可选能力缺失时，让对应控件说明不可用原因。API 参考列出每个操作的准确权限和允许阶段。

读取成功不代表可以修改。之前的授权也可能被撤销，因此即使能力检查为可用，调用仍需处理拒绝结果。

## 保持句柄归属

ID、版本、游标、文件授权、计划和订阅都是不透明值。原样保存，不要从目录名构造 ID、递增版本、转换句柄类型或跨插件复用游标。归属包含当前加载实例；重新加载后要获取新句柄。

## 由宿主确认修改

有预览或准备步骤的操作，应先生成计划，展示计划绑定的真实摘要，再按宿主确认结果执行同一个计划。等待确认期间目标可能变化，宿主会重新检查；必要时重新生成计划并再次确认。

拒绝确认不得执行回调。确认界面不可用也不代表同意。结果不确定时保留原幂等键和输入，先检查任务；换一个键可能造成第二次副作用。

## 不跨越领域授权

文件授权不自动包含父目录、相邻文件或范围外的符号链接目标。公开账户信息不包含令牌。网络请求仍受目的地址策略约束。只读 Provider 回调不能嵌套执行宿主修改。

测试时移除一项权限、重建插件并重复对应操作，确认失败被准确展示，且不存在绕过拒绝的备用路径。再验证停止后旧句柄不能被新加载继续使用。
