# 测试、打包与发布

发布前需要分别验证包内容、契约和宿主行为。ZIP 可以解压，只能说明容器可读；编译成功，也不能证明确认、授权和取消符合预期。

## 从固定输入构建

在模板仓库执行：

```sh
python eng/build.py --clang clang
python eng/verify_package.py
```

保存源码、配置、SDK 锁文件和编译器版本。要求字节级复现时，对同一工具链构建两次并比较摘要；不同编译器版本不保证生成相同 Wasm。

## 验证实际行为

| 场景 | 预期结果 |
| --- | --- |
| 首次加载 | 必需能力协商成功，页面仅在激活后出现 |
| 权限拒绝 | 对应功能明确失败，没有绕过路径 |
| 拒绝动作确认 | 回调不执行 |
| 重复请求 | 幂等键仍绑定原输入 |
| 取消 | 展示实际终态或不确定结果，不虚构回滚 |
| 停止和重载 | 旧注册消失，新加载重新获取句柄 |
| 缺少可选能力 | 核心功能仍可使用，不可用部分说明原因 |
| 离线重启 | 已准入的本地内容在宿主策略允许范围内工作 |
| 篡改资源 | 未验证内容不执行 |

修改真实数据的测试应使用独立测试配置和可丢弃内容。SDK 测试验证类型与编解码，PluginSidecar 测试验证执行，NexaCL 集成测试验证实际业务所有者，三者不能相互替代。

## 说明分发边界

发布说明列出插件版本、测试过的最低宿主版本、SDK 版本、必需契约、权限和迁移要求。附上经过核验的包及摘要，保留不可变的旧发布物。

摘要证明字节一致，不证明发布者身份。开发者模式下的未签名 ZIP 不等于生产 Market 已批准的插件。更新 SDK 时同时审阅锁文件、托管示例的包版本及宿主支持范围，再重新构建和验证。
