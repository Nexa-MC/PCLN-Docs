# 排查加载或调用失败

先找最早的结构化错误及所在阶段。退出清理时的异常可能遮住起因，应保留两者；不能只报告最后一个异常，也不能把默认值当作成功结果。

## 收集可用证据

记录插件 ID 和版本、SDK 版本、宿主版本、阶段、错误码、操作或关联 ID，以及相关加载报告。提供最小复现源码或包。分享前删除账户令牌、授权句柄、私密文件和分发密钥。

| 现象 | 优先检查 | 处理方式 |
| --- | --- | --- |
| 找不到 wasm-ld | LLVM 安装和 PATH | 修复工具链 |
| SDK 或资源摘要不符 | 锁定版本与实际字节 | 恢复已验证内容或重新构建，不能跳过校验 |
| 必需能力不可用 | 实际宿主版本及协商结果 | 换用兼容宿主或缩小功能需求 |
| 权限拒绝 | 精确权限与目标范围 | 说明限制，通过宿主正规流程请求授权 |
| STAGE_FROZEN | 保存的视图和回调寿命 | 在正确阶段使用当前范围 |
| schema 不符 | 描述符、编码器与指纹 | 同时修正生产者和消费者 |
| 版本冲突 | 读取后目标是否变化 | 重新读取、合并并准备计划 |
| 回调未运行 | 激活、处理器编号、注册和确认结果 | 核对调用链；拒绝确认本就不应执行 |
| 订阅缺口 | 溢出、保留期和重启 | 重新读取权威快照 |
| OUTCOME_UNKNOWN | 任务记录和外部状态 | 核实结果，禁止盲目重放 |

## 区分超时与副作用失败

超时可能发生在外部系统已经执行之后。取消也不会自动撤销完成的操作。应检查任务或持久日志；没有证据前保持结果不确定。

在同一个宿主先运行未修改模板，再加入一个失败能力和一次调用。验证成功路径与准确的拒绝、冲突或取消场景。报告中注明验证层次：SDK 编解码测试通过，不等于实际宿主业务已经可用。
