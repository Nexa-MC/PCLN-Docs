# 测试、排错与发布

## 发布前检查

1. 检查根目录 mimetype、严格 JSON、版本和 NSS 路径；不要把整个父目录打包进去。
2. 使用主题包导入、预览、应用、重启、恢复默认和卸载验证完整生命周期。
3. 测试每个选项、错误输入、滑块拖动、键盘焦点及实时保存失败后的重试。
4. 在亮/暗模式、窄窗口、减少动态效果及缺少可选材质能力时检查可读性。
5. 对外部文件授权测试取消选择、撤销和重新导入；不得沿用另一来源的授权。

## 容器预算

清单最大 64 KiB、深度 16；最多 4096 个归档项、256 个选项、64 个 NSS 文件，NSS 合计最多 1 MiB。压缩包/单项上限 128 MiB，总实际展开最多 512 MiB。链接、路径穿越、绝对路径、重复项及跨平台歧义文件名会被拒绝；资源还有独立的类型和解码预算。

## 常见问题

| 现象 | 检查 |
|---|---|
| 导入失败 | mimetype、根路径、未知 JSON 字段、重复字段、大小预算 |
| 选项被拒绝 | kind 与 default/control 匹配、选择值、步长及边界 |
| 样式没变化 | styles 顺序、目标选择器、能力、草稿是否完整 |
| 资源缺失 | 包内实际文件、资源类型、授权来源及路径 |
| 某系统特效失效 | 原生支持与可选能力 fallback；不要只验证编译 |

## 可重复检查

```sh
# 在 NexaCL 源码目录打包；同样输入产生同样 ZIP 内容
python eng/themes/pack.py ../PCLN-Docs/examples/themes/twilight --output ../twilight.ntp
# 在隔离的数据目录运行开发版发布检查
Nexa.Desktop --validate-themes
```

后一命令需要真实可执行文件与随包资源，不是用户导入主题的必需步骤。开发验证应设置独立 `NEXA_DATA_DIR`，避免改动常用配置。

分发 `.ntp` 时附版本、适用宿主版本、能力/平台要求、许可及资源授权说明。NTP/1 外观包不使用启动器更新私钥；打包成功也不代表宿主已准入，更不代表允许执行程序。
